== So, WHICH UI Libraries do Wizards Use?

The ultimate context to imagine is the single {bounded-context} domain behavior service,
like in mSaaS or µSaaS vendor applications -- and you are the vendor -- what do you do?!

."No shared UI" is the choice we always make {c4w-bitspittle}.
[#img-no-shared-ui-plug,link={imagesdir}/android-studio-no-shared-ui.png]
image::android-studio-no-shared-ui-plug.png[No shared UI choice]

So, once you split off the tree -- what's there?
"Do not share UI (React)" is not a Gradle module, it's your ordinary JS project.
It doesn't need to be React -- it can be anything!
See {read-model-repo} on how to make it a proper Gradle module consuming your Kotlin magic.

== Vue 3 -- Corporate React {plus}{plus}

I MEAN the {vue}, not 2 -- a very different animal.
Compiler-informed VDOM, fully {vue-composition-api}, ES6 Proxies -- a solid swap for React in corporate America.
And, I find it easier to teach than React.

== SolidJS -- Performance Choice

{solidjs} is an entirely different paradigm -- compiled, no VDOM. I dig! The few SPAs I built with it performed very well.
I could demo Solid in {read-model-site} if page performance was the key.

Remarkable here is the 2-stage process that packages reactive JSX components into vanilla JavaScript DOM operations.
Then everything just works client-side as if an engine were there.

== Qwik -- Resumable Rendering

{qwik} is not my cup of tea, but many distributed systems folks now reach for it.

The "new" paradigm here is {qwik-resumable} instead of hydrating the DOM.
And the entire magic is driven by the *_lazy loading_*.
Competent engineers use plenty of *_lazy_* where it fits logically.
Here, everything is lazy. The key to the perfect {lighthouse} performance score is to use LESS JavaScript.
So, colloquially, a 20% faster site makes 10% more conversions. That makes me think a "landing page."

99% of the time I make a read model -- the presentation for some aggregate functional behavior.
For that I need the opposite of "lazy loading" -- a clean, self-contained business function upfront.

> Maybe I'm missing something -- clue me in the comments, please.
